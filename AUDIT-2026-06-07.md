# Audit site bertrandbasset.com — 07 juin 2026

## 1. Supabase — incohérences critiques

### 1.1 `section_visibility` : 20+ lignes mortes pour les cartes

**Le moteur ne lit `section_visibility` QUE pour les items de `MENU_CONFIG`** (les entrées de nav : photographe, réalisateur, boutique…). Il ne lit PAS `section_visibility` pour la visibilité des cartes — celle-ci est controlée par `gallery_cards.visible`.

Or la table contient des entrées pour des IDs de cartes (`ph-portrait`, `ph-gem`, `ph-serie-expo`, `real-television`, `shop-boutique-portrait`…) : elles n'ont **aucun effet** sur le site.

**Entrées mortes confirmées dans `section_visibility` :**
| ID | Problème |
|----|----------|
| `ph-portrait`, `ph-gem`, `ph-serie-expo`, `ph-dustin-kolor-ph`, `ph-plougasnou`, `ph-salarie-ehpad`, `ph-carre-das`, `ph-lumiere`, `ph-plateau`, `ph-immersion`, `ph-st-melar`, `ph-burning-man`, `ph-galeries-client` | IDs de cartes — ignorés par le moteur |
| `real-cinema`, `real-television`, `real-portrait-invite`, `real-corporate` | Idem |
| `shop-boutique-dk`, `shop-boutique-portrait`, `shop-boutique-studio-mobile`, `shop-boutique-projet` | Idem |
| `ph-stmelar` | Ancien ID (sans tiret dans "melar") — doublon mort |
| `boutique-dk`, `boutique-portrait`, `boutique-projet` | Anciens IDs MENU_CONFIG masqués statiquement (`hidden: true`) — ces entrées n'ont aucun effet |

**Conséquence pratique :** L'onglet "Visibilité menu" de l'admin affiche et écrit ces entrées, mais elles ne changent rien sur le site. L'admin est partiellement trompeur.

**Résolution :** Nettoyer ces lignes dans Supabase ET comprendre pourquoi l'admin les écrit (bug dans la logique de génération des items de l'onglet visibilité).

---

### 1.2 `ph-carre-das` : image cassée

`gallery_cards.cover_img = "images/photography/portrait/placeholder-8.jpg"` — chemin inexistant.
Le vrai chemin est `images/portrait/placeholder-8.jpg`.

De plus : `gallery_cards.visible = true` + `gallery-data.js._hiddenByAdmin = true` → la logique du moteur rend la carte **visible** (car `wasStaticHidden=true` + `row.visible=true` → `_hiddenByAdmin=false`). La carte Carré d'As s'affiche donc en production avec une **image cassée**.

**Résolution :** Corriger le chemin dans Supabase → `images/portrait/placeholder-8.jpg`. Décider si la carte doit être visible ou non.

---

### 1.3 `ph-immersion` : galerie quasi-vide exposée

`gallery_cards.visible = true` + `gallery-data.js._hiddenByAdmin = true` → carte **visible** (même logique que ci-dessus). Elle ouvre la galerie `studio` qui pointe sur `images/immersion/` — **dossier vide** (1 fichier .DS_Store). Le dossier `images/STUDIO/` n'a que des placeholders (`placeholder-1.jpg`, `placeholder-3.jpg`, `placeholder-portrait-pro.jpg`).

Un visiteur cliquant "Immersion" arrive sur une galerie vide ou avec des placeholders.

**Résolution :** Mettre `gallery_cards.visible = false` pour ph-immersion, ou créer le contenu réel d'abord.

---

### 1.4 `ph-burning-man` : carte visible mais non fonctionnelle

`gallery_cards.visible = true` + `_hiddenByAdmin = true` en statique → carte **visible**. Mais `galleryId = null` dans `gallery-data.js`, aucune surcharge dans Supabase → le clic ne fait **rien** (`onclick="void(0)"`).

La cover `images/burning man/prise de vue sans titre-6273.jpg` existe (35 photos dans le dossier), mais la galerie `burning-man` n'est pas définie dans `GALLERIES_CONFIG`.

**Résolution :** Soit créer la galerie `burning-man` dans `GALLERIES_CONFIG` + `gallery-data.js`, soit passer `visible = false` dans Supabase.

---

### 1.5 Double architecture galeries clients dans PHOTOGRAPHE

Supabase a des rows `ph-gilmerton`, `ph-leo-brasserie`, `ph-plougasnou` en `section: photographe` avec `parent_id: 'ph-galeries-client'`. Cela crée un sous-groupe **"Galeries Client" dans la section PHOTOGRAPHE** (via `showSubGrid`).

Simultanément, une section séparée `galeries-client` existe dans `SECTIONS_CONFIG` avec les mêmes galeries (gilmerton, leo-brasserie, grande-parade).

Deux chemins d'accès différents pour les mêmes galeries clients. Architecture à clarifier.

### 2.3 Galerie `corporate` : sans images

`GALLERIES_CONFIG["corporate"].images = []`. La carte "Corporate & Web" dans RÉALISATEUR ouvre une galerie avec uniquement un carton qui contient un lien pCloud externe (qui peut expirer). Pas d'images photo.

### 2.4 `FILMS_VIDEOS` : 9 vidéos sans `videoId`

La page "films-player" liste 11 vidéos. Seule **J'arrive** a un `videoId` Vimeo (`240574987`). Les 10 portraits France 2 ont `videoId: ""` → l'iframe chargera `about:blank`. La page VOIR LES FILMS est en grande partie **non fonctionnelle**.

**Résolution :** Soit retrouver les IDs YouTube/Vimeo des portraits France 2, soit afficher ces entrées différemment (vignette statique sans player).

---

### 2.5 Archives : 4 images dans le dossier absentes de la config

`images/archives/` contient 10 fichiers (01.jpg → 10.jpg). `GALLERIES_CONFIG["archives"].images` liste seulement 6 (01, 06, 07, 08, 09, 10). Les fichiers 02, 03, 04, 05 sont dans le dossier mais **non affichés**.

Intentionnel ou oubli ? À vérifier.

### 2.6 Portrait : images Plougasnou dans `gallery-images.js`

`gallery-images.js` inclut `Atelier_Plougasnou.jpg` et `Atelier_Plougasnou 1.jpg` dans la liste de la galerie `portrait`. Ces photos apparaissent donc **dans la galerie Portrait du site principal**. Probablement non voulu.

### 2.7 St Mélar : double définition

Les 6 images de St Mélar sont déclarées à la fois dans `gallery-images.js` et dans `GALLERIES_CONFIG["st-melar"].images`. Le moteur donne la priorité à `GALLERY_IMAGES`, donc pas de bug, mais c'est redondant. À nettoyer (supprimer de `GALLERIES_CONFIG.images` puisque `gallery-images.js` fait foi).
